# 使用指南

[文档首页](README.md) · [兼容性与限制](compatibility.md)

## 一次任务的过程

正常向机器人发消息即可。插件收到普通入站后创建回执，随后在同一条消息中更新实际阶段：

```text
收到，正在处理…
  → 正在思考…
  → 正在搜索资料… / 正在执行工具…
  → 正在整理结果…
  → 成功后清理
```

阶段取决于宿主实际发出的事件，不保证每个任务都经历全部阶段。最终答案、附件、Markdown 和引用由 OpenClaw 正常发送。

文本任务优先在原生发送确认后清理气泡。部分附件路径没有发送确认，明确成功结束后会等待 5–10 秒再清理；附件是否送达以聊天中的实际文件为准。

## 具体进度与等待

多步骤任务中，当前模型可以调用 `tgux_progress` 提交一句面向使用者的工作说明。未调用时继续展示真实事件阶段，无需额外设置。

详细模式会增加工作说明和经过时间；超过 30 秒没有新事件时显示等待提示。时间经过不代表任务取得进展，也不表示百分比完成。

| 模式 | 展示内容 |
| --- | --- |
| `compact` | 当前阶段、补充收件提示 |
| `detailed` | 当前阶段、可用的工作说明、经过时间、等待提示，以及可关联的后台任务状态 |

## 设置与帮助

```text
/tgux
/tgux help
/tgux lang zh
/tgux lang en
/tgux style compact
/tgux style detailed
```

默认中文、详细模式。偏好按账号和聊天保存，重启后保留；切换界面语言不会翻译已有的模型工作说明，也不会改变最终答案语言。

## 补充要求与停止

任务运行中继续发消息，插件会显示“补充已收到”。是否以及何时处理这条补充，由原生 steer 或队列决定。

停止使用原生 `/stop`，或整条消息“停止”“停下来”“暂停”。插件在观察到明确取消事件后显示“已停止。”。“暂停”在此处是停止短句，不支持稍后恢复这个任务。

停止后可直接发起新请求。跟踪超时、插件重启等状态提示只描述进度显示本身；检查原生运行状态可使用 `/status`。

## 交互菜单（Beta）

`/tgux` 可显示状态、帮助、语言和显示方式按钮；最近任务完成后，还可显示“继续解释”和“简要总结”。

菜单有效期为 10 分钟。打开新菜单、重启服务或任务代次变化后，旧操作可能失效。续问仅适用于菜单对应的最近任务，不提供停止按钮。

**当前版本已实测菜单显示和文字命令；按钮回调与续问尚待真实 Telegram 补验。** 权限、消息归属、重复和过期回调已有自动化覆盖，详见[版本验证记录](releases/0.2.0-beta.1-validation.md)。
